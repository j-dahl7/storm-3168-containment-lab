# Storm-3168: When Does a Compromised Service Principal Actually Lose Access?

A reproducible Microsoft Sentinel and Azure containment study for [Nine Lives, Zero Trust](https://nineliveszerotrust.com/). The question is when a **specific capability** stops working after a response action, and what access remains.

**Status: experimental implementation; publication and independent Claude Code review pending.** Offline tests, template compilation, live infrastructure deployment and measured containment are separate evidence categories. See `docs/verification-status.md` for the current record. Unrun matrix cells stay `not_tested`; fixtures are explicitly synthetic.

Microsoft's [September 25 investigation](https://www.microsoft.com/en-us/security/blog/2026/09/25/storm-3168-agentic-driven-cloud-attacks-using-compromised-service-principals/) is the motivation. Its 90-minute interval separates two identities' initial enumeration; it is not a proven warning-to-wipe window. The leaked secret was a possible initial-access path, not a confirmed one. This lab does not recreate malware or claim that every behavior can be attributed to that actor.

## Offline quick start

Python 3.12+ and Git are required. Runtime code uses the standard library.

```powershell
python -m pip install -e .
python -m unittest discover -s tests -v
python scripts/validate_assets.py
python fixtures/validate_artifacts.py
python -m stormlab demo --output private/demo.jsonl
python -m stormlab summarize --input private/demo.jsonl --output private/demo-summary.json
```

The demo refuses to overwrite an existing file. It is simulated evidence and makes no Azure calls. CI does not sign in to Azure or run containment actions.

## Live setup is an explicit step

Read the protocol first. Azure CLI must be signed in to the intended tenant. Use your own subscription UUID and region. The examples below contain placeholders, not usable identifiers.

```powershell
python scripts/setup_lab.py --subscription SUBSCRIPTION_UUID --budget-usd 10 --enable-sentinel
# After reviewing the printed plan:
python scripts/setup_lab.py --subscription SUBSCRIPTION_UUID --budget-usd 10 --enable-sentinel --execute
python -m stormlab preflight --manifest private/manifest.json --subscription SUBSCRIPTION_UUID
```

Setup refuses to adopt an existing group or overwrite a manifest. It records completed stages in `private/manifest.json`. On interruption, reconcile that exact state. The two bounded resume flags handle only their documented recorded stages; they are not generic permission to retry partial mutations.

Storage starts with Shared Key disabled, public blob access disabled and a deny-default data-plane firewall. ARM-only trials do not require blob access. A copied-key/SAS experiment needs an explicitly configured canary blob and permitted test source before any baseline can succeed; a firewall failure must not be called credential revocation.

Use the optional [storage-baseline protocol](docs/storage-baseline.md) to prepare that data path. It defaults to plan-only and never opens a broad source range. New live cases must wait for the independent Claude recheck; preparation itself is not evidence that the actor's credential works.

No VM, paid threat feed, Workload Identities Premium policy or tenant-wide diagnostic export is installed by default. Workload Conditional Access/risk policies remain **not tested** unless separately licensed and selected. The USD 10 usage target and workspace ingestion quota are not hard spending caps. Review regional pricing, bound runtime and clean up recorded resources.

## Fixed-token trial

Prepare the exact direct/group access path before each independent trial. Retain Reader while removing Storage Account Contributor so the tag-write probe can inspect the account without preserving write access.

```powershell
python scripts/configure_access.py --manifest private/manifest.json --subscription SUBSCRIPTION_UUID --confirm-lab-id LAB_UUID --mode direct
python scripts/configure_access.py --manifest private/manifest.json --subscription SUBSCRIPTION_UUID --confirm-lab-id LAB_UUID --mode direct --execute
python scripts/live_trial.py --manifest private/manifest.json --subscription SUBSCRIPTION_UUID --confirm-lab-id LAB_UUID --action none --duration 60 --execute
```

Then run one selected action, for example `sp-disable` or `role-delete` with the exact writer assignment ID from the private manifest. The selected action remains applied; the wrapper removes only its temporary credential, not the response action. Restore and verify the baseline before a new trial. Never supply a token/secret/key as a command-line argument.

Use `--check-new-token` only when the separate issuance control is part of the
trial. Its returned token is discarded and never replaces the frozen probe.
Initial credential propagation retries occur before the probe token is acquired;
the private receipt records those attempts. Baseline collection requires at
least two allowed observations before applying a response.

For a manually prepared credential, `python -m stormlab probe --help` documents environment-variable names for bearer, Shared Key and SAS inputs. SAS input is only a read-only, HTTPS query string with explicit expiry; the target URL always comes from the manifest's exact canary blob. The harness never refreshes that credential or follows redirects.

Tag probes preserve existing tags, use the Storage account API and check the resulting nonce. Serialize tag writers: this is not an atomic concurrent update protocol. The API may reject a write, accept it without verified completion, or fail before writing; those are distinct outcomes.

## Response and measurement

`respond` plans by default. A mutation requires `--execute`, `--confirm-lab-id`, the selected subscription and successful live ownership/identity checks. Lock actions are explicitly named `lock-readonly`, `lock-cannotdelete`, and `lock-remove`; removal applies only to the recorded lab-owned lock. No playbook automatically removes locks.

Service-principal disablement, app deactivation, secret removal, direct role deletion, group-role deletion, group-membership removal, key1/key2 rotation and Shared Key disallow are separate experiments. Do not combine them and attribute a timing to one action. App-level deactivation availability is verified per tenant/API; a rejected request stays failed/not tested.

Record at least three independent valid trials per claimed action. Token expiry, a 429, transport failure or an unverified write does not establish containment. A specific denied capability does not prove that other tokens, copied keys or SAS credentials stopped working. Baseline and post-action files in a `live_trial.py` directory share the one token by the runner's construction; their separate harness run IDs must be reconciled using the trial receipt.

## Review and publication

The public source contains no live tokens, keys, tenant manifests or raw tenant evidence. Sanitized reports must identify source revision, trial count, censoring, missing telemetry and exclusions. Do not populate measurements from documentation expectations.

The website integration remains draft until review and the relevant live evidence are complete. Its provenance gate expects a public `j-dahl7` source repository and a real pinned commit reachable from that repository's default branch. Any bundled source must exactly match that tree.
